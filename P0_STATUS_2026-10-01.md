## What Happens Automatically After Data Provision

### Stage 1: Provenance Audit (automatic)
```bash
python -m src.layers.layer3_wyckoff.data_provenance_audit
```
**Checks**:
- ✅ File exists & readable
- ✅ Valid OHLCV JSON format
- ✅ No duplicate timestamps
- ✅ No missing candles (gap detection)
- ✅ No pre-launch data (SOL ≥ 2020-03-20)
- ✅ Compute SHA-256 for integrity

**Result**: PASS or FAIL (blocks WFV if FAIL)

### Stage 2: WFV Window Generation (automatic)
```bash
python -m src.layers.layer3_wyckoff.real_data_wfv_pipeline
```
**Generates**:
- 71 rolling windows (60-day train, 30-day test, 30-day step)
- Timestamp boundaries for each window
- PIT validation checks (no lookahead bias)

### Stage 3: Point-In-Time (PIT) Validation (automatic)
**Checks**:
- ✓ No forward-fill in train data
- ✓ SMA-200 lookback >= 200 days
- ✓ Smart Money lag >= 1 day
- ✓ Train/test split strict (no overlap)
- ✓ RSI/volume computation correctness

**Result**: PASS or FAIL (blocks backtest if FAIL)

### Stage 4: BCE Backtest on Test Windows (automatic)
For each of 71 windows:
- Run BCE scoring on test period
- Generate buy/sell signals
- Compute OOS trade metrics

### Stage 5: Immutable Gates (automatic)
Apply frozen thresholds to aggregate metrics:

| Gate | Requirement | Block |
|------|-------------|-------|
| OOS Trades | >= 200 | ❌ Fail if < 200 |
| Profit Factor | >= 1.30 | ❌ Fail if < 1.30 |
| Max Drawdown | < 25% | ❌ Fail if >= 25% |
| Degradation | < 30% | ❌ Fail if >= 30% |
| Consistency | >= 50% | ❌ Fail if < 50% |

### Stage 6: Phase 3 Verdict (automatic)
Generates final verdict:
- **✅ PASS**: All gates satisfied → Phase 4 X20 unlocked
- **❌ FAIL**: Metrics don't meet gates → Phase 4 remains blocked
- **⚠️ INCONCLUSIVE**: Data quality issues → Investigate & retry
