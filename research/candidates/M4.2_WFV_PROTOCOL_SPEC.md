## 3. Strict PIT Validator

### Period-In-Time (PIT) Backtest

Validate X20 strategy on **single, unlocked training window** (no walk-forward).

**Configuration:**
```
Training window: 2024-01-01 to 2025-06-30 (18 months)
Testing window: NOT USED in PIT (locked before execution)
Strategy: X20 entry/exit rules with fixed parameters (see Layer 4 spec)
Baseline: Price momentum + volume surge (naive benchmark)
```

**Execution steps:**
1. Load training OHLCV (locked, no modifications)
2. Generate X20 signals on each bar (no lookahead)
3. Execute trades with stops/targets
4. Record IC (Information Coefficient) vs baseline
5. Report pass/fail: IC > baseline IC by ≥15%?

**Output metrics:**
```
{
  "stage": "PIT",
  "data_hash": "sha256(training_data)",
  "total_trades": N,
  "hit_rate": float (0-1),
  "ic_vs_baseline": float,
  "profit_factor": float,
  "max_drawdown": float,
  "passed": bool,
  "timestamp": "2026-10-06T13:59:14Z"
}
```

## 4. Fold Generator with Derived Dates

### Rolling Window Folds

Create non-overlapping in-sample / out-of-sample folds using **calendar-based splits** (no data-driven optimization).

**Algorithm:**

```python
def generate_folds(start_date, end_date, fold_size_months=6, gap_months=0):
    """
    Generate walk-forward folds with locked boundaries.
    
    Args:
        start_date: 2024-01-01
        end_date: 2026-10-06
        fold_size_months: 6 (in-sample = 6 months, out-sample = 3 months)
        gap_months: 0 (no gap between folds)
    
    Yields:
        (fold_id, is_start, is_end, in_sample_period, out_sample_period)
    """
    fold_id = 1
    current = start_date
    
    while current < end_date:
        is_start = (current == start_date)
        
        # In-sample: 6 months
        is_end_train = current + 6*months
        if is_end_train > end_date:
            break
        
        # Out-of-sample: next 3 months (locked before training)
        os_end = is_end_train + 3*months
        if os_end > end_date:
            os_end = end_date
        
        is_end = (os_end >= end_date)
        
        yield {
            "fold_id": fold_id,
            "is_start": is_start,
            "is_end": is_end,
            "in_sample": (current, is_end_train),
            "out_sample": (is_end_train, os_end),
            "gap_days": 0,
            "locked_at": datetime.utcnow()
        }
        
        fold_id += 1
        current = os_end
```

**Fold properties:**
- Non-overlapping in time
- Boundaries fixed BEFORE any training
- No optimization of fold dates
- No data snooping in fold selection

## 5. Out-of-Sample (OOS) Protocol

### Rolling Window Validation

For each fold:

1. **Lock fold boundaries** (timestamp, sign)
2. **Train on in-sample data** (X20 parameter search on locked window)
3. **Freeze parameters** (sign checkpoint)
4. **Test on out-sample data** (no retraining, no parameter updates)
5. **Record metrics** (separate in-sample vs out-sample)
6. **Compute degradation** (out-sample performance ÷ in-sample performance)

**Execution pseudo-code:**

```python
for fold in generate_folds(...):
    # Lock fold (immutable)
    is_data = load_ohlcv(fold.in_sample)
    os_data = load_ohlcv(fold.out_sample)
    
    # Train (parameter optimization on locked IS data)
    params = optimize_x20_params(is_data, locked=True)
    is_results = backtest(is_data, params)
    
    # Test (apply frozen params to OOS data)
    os_results = backtest(os_data, params)
    
    # Metrics
    is_ic = compute_ic(is_results, baseline)
    os_ic = compute_ic(os_results, baseline)
    
    degradation = os_ic / is_ic  # Should be close to 1.0
    
    record({
        "fold": fold.fold_id,
        "is_ic": is_ic,
        "os_ic": os_ic,
        "degradation": degradation,
        "is_trades": len(is_results),
        "os_trades": len(os_results),
        "passed": degradation > 0.7  # ≥30% degradation = failure
    })
```

## 6. Metrics: IC, Hit-Rate, Stability, Ablation

### Information Coefficient (IC)

**Definition:** Correlation of X20 signal (continuous score 0-100) with next-period returns.

```
IC = Spearman rank correlation(
    signal_at_t,
    returns_t+1_to_t+20_days
)
```

**Baseline (naive):** Price momentum + volume surge (no ML)

**Gate:** `IC_X20 > IC_baseline + 15%` (absolute, not relative)

### Hit-Rate

**Definition:** Fraction of trades with positive P&L (close > entry).

```
hit_rate = (winning_trades) / (total_trades)
```

**Gate:** Hit-rate ≥ 45% (loose threshold; IC is primary gate)

### Stability (Cross-Fold Consistency)

**Definition:** Coefficient of variation of IC across folds.

```
stability_score = 1 - (std_dev_ic / mean_ic)
```

**Gate:** Stability ≥ 0.60 (60% of mean, ≤40% variation)

### Ablation Tests

Measure contribution of each X20 component:
1. Remove momentum → IC drop = ?
2. Remove volume → IC drop = ?
3. Remove structure → IC drop = ?
4. Remove sentiment → IC drop = ?

**Gate:** No single component explains >60% of IC (avoid over-reliance on one signal)

## 7. Gate Criteria with Source/Justification

### M4.2 Validation Gate (STRICT)

| Criterion | Threshold | Source | Justification |
|-----------|-----------|--------|----------------|
| **IC vs Baseline** | IC_X20 > IC_baseline + 15% | IGWT-PF26 Phase 4 spec (Layer 4) | X20 must add measurable signal beyond naive baseline |
| **Cross-fold stability** | ≥0.60 | Walk-forward best practices | Consistency across time periods = robustness |
| **Hit-rate minimum** | ≥45% | Statistical significance threshold | False signals would yield <40% on noise |
| **Ablation independence** | No component >60% | Multi-signal architecture requirement | Avoid single-factor dominance |
| **OOS degradation** | ≤30% (degradation_ratio ≥0.70) | Overfitting detection | Out-sample performance should track training |
| **Minimum trades** | ≥50 per fold | Statistical power requirement | Fewer trades = high noise in metrics |

### Decision Logic

```
Gate PASS if:
  (IC_X20 > IC_baseline + 15%)
  AND (stability ≥ 0.60)
  AND (hit_rate ≥ 0.45)
  AND (no_ablation_component > 0.60)
  AND (avg_degradation ≤ 0.30)
  AND (total_trades ≥ 50)

Gate FAIL if:
  Any criterion fails OR no real data available
```

## 10. Rejection Criteria (What Invalidates M4.2)

M4.2 is **rejected** if any of these occur:

1. **Data contamination:** Forward-fill, synthetic interpolation, or post-observation adjustments
2. **Lookahead bias:** Fold dates optimized on future returns
3. **Parameter snooping:** X20 thresholds optimized on OOS data
4. **Insufficient folds:** Fewer than 3 non-overlapping windows
5. **Missing ablation:** No decomposition of X20 components
6. **Threshold invention:** Gate criteria without Layer 4 spec justification
7. **Degradation >50%:** Out-sample IC drops >50% vs in-sample (strong overfitting signal)
8. **No audit trail:** Unsigned, undated, unversioned artifacts
